Module 1: Introduction & Setup (30 minutes)

Learning Objectives

1.1 What is Amazon Q Developer?

Amazon Q Developer is a generative AI-powered assistant that helps developers build, transform, and operate applications on AWS. For SAP ABAP developers, it provides:

  • Code generation — Write ABAP code from natural language descriptions
  • Code explanation — Understand legacy ABAP programs instantly
  • Code transformation — Modernize classical ABAP to Clean ABAP / ABAP Cloud
  • Debugging assistance — Identify and fix runtime errors, performance issues
  • Documentation — Auto-generate technical documentation

1.2 What is Kiro?

Kiro is an agentic AI IDE from AWS that goes beyond code completion. It uses spec-driven development to turn natural language prompts into structured requirements, system designs, and implementation tasks. Key features:

  • Spec-driven development — Turns prompts into requirements, design, and tasks before writing code
  • Agent hooks — Automate tasks like generating docs and tests on file save
  • Steering files — Configure coding standards and preferred workflows per project
  • Built on Code OSS — Familiar VS Code experience, import your existing settings and extensions
  • Native MCP support — Connect to docs, databases, APIs, and more

1.3 Supported ABAP Patterns

Amazon Q and Kiro understand: - Classical ABAP (reports, module pools, function modules) - ABAP Objects (classes, interfaces) - CDS views and ABAP annotations - RAP (RESTful ABAP Programming Model) - ALV programming (classical and OO) - SAP-specific tables, BAPIs, and transactions

## Coding Standards
- Follow Clean ABAP guidelines
- Use modern ABAP syntax (inline declarations, string templates, NEW operator)
- No SELECT * — always use explicit field lists
- No SELECT inside LOOP — use JOINs or FOR ALL ENTRIES

- Local variables: lv_, lt_, ls_, lo_, lr_, lx_

- Interfaces: zif_ prefix

- Use released APIs where possible

2.1 Prompting Strategies for ABAP

Effective prompts for ABAP code generation should include:

  1. Context — SAP module (MM, SD, FI), system version (ECC, S/4HANA)
  2. Specifics — Table names, field names, transaction codes
  3. Standards — Clean ABAP, naming conventions, modern syntax
  4. Output format — Report, class, CDS view, function module

Good vs. Bad Prompts

❌ Vague Prompt ✅ Specific Prompt
Write code to read purchase orders Write an ABAP report for S/4HANA that reads purchase orders from EKKO/EKPO, filters by company code (BUKRS) and creation date (AEDAT) using selection screen parameters, and displays results in an ALV grid using CL_SALV_TABLE
Create a CDS view for sales Create a CDS view entity joining VBAK and VBAP with associations to I_BusinessPartner and I_Product, exposing sales order number, item, material, quantity, net value, and currency

Learning Objectives

3.1 Why Code Explanation Matters

SAP systems often contain decades of custom ABAP code with: - Minimal or outdated documentation - Complex business logic embedded in nested loops - Dynamic programming (field symbols, ASSIGN, GENERATE SUBROUTINE POOL) - Implicit dependencies on SAP standard behavior

Amazon Q can analyze ABAP code and explain the business logic, data flow, and potential issues.

Hands-On Lab 3.1: Explain Legacy Code

Instructions

  1. Copy the following legacy ABAP code into your editor or the Amazon Q chat:
REPORT z_legacy_sales_report.

TABLES: vbak, vbap, kna1.

DATA: lt_vbak TYPE TABLE OF vbak,
      ls_vbak TYPE vbak,
      lt_vbap TYPE TABLE OF vbap,
      ls_vbap TYPE vbap,
      lv_total TYPE vbap-netwr,
      lv_count TYPE i,
      lt_kna1 TYPE HASHED TABLE OF kna1 WITH UNIQUE KEY kunnr.

SELECT-OPTIONS: s_erdat FOR vbak-erdat,
                s_vkorg FOR vbak-vkorg.

START-OF-SELECTION.

SELECT * FROM vbak INTO TABLE lt_vbak
  WHERE erdat IN s_erdat
    AND vkorg IN s_vkorg
    AND vbtyp = 'C'.

IF lt_vbak IS NOT INITIAL.
  SELECT * FROM kna1 INTO TABLE lt_kna1
    FOR ALL ENTRIES IN lt_vbak
    WHERE kunnr = lt_vbak-kunnr.
ENDIF.

LOOP AT lt_vbak INTO ls_vbak.
  SELECT * FROM vbap INTO TABLE lt_vbap
    WHERE vbeln = ls_vbak-vbeln.
  CLEAR lv_total.
  LOOP AT lt_vbap INTO ls_vbap.
    lv_total = lv_total + ls_vbap-netwr.
    lv_count = lv_count + 1.
  ENDLOOP.

🔌 MCP for SAP ABAP — Connect Your IDE to SAP

The Model Context Protocol (MCP) is an open standard that lets AI assistants (Amazon Q, Kiro, Claude) connect directly to external tools and data sources. For SAP ABAP, this means your AI assistant can read source code, table structures, and data directly from your SAP system — no copy-pasting needed.

🎯 Why MCP matters for ABAP developers:
  • Ask "explain program SAPMV45A" → AI reads the source code directly from SAP
  • Ask "what fields are in table VBAK?" → AI queries the table definition live
  • Ask "find all programs that use BAPI_SALESORDER_CREATEFROMDAT2" → AI runs where-used analysis
  • No more copy-pasting code into chat — the AI fetches it automatically

MCP Troubleshooting
MCP server won't connect
Check that the SAP system URL is reachable from your machine. Try curl https://your-sap-system:443/sap/bc/adt/discovery — you should get an XML response. Also verify the /sap/bc/adt service is active in SICF.
Authentication error (401)
Double-check your username, password, and client number in the .env file. If your password contains special characters like #, wrap it in quotes.

Increase the timeout in your MCP config from 60 to 120 seconds. Large programs like SAPMV45A can take time to retrieve.
SSL certificate errors
If your SAP system uses self-signed certificates, set SAP_VERIFY_SSL=false in your .env file (not recommended for production).
